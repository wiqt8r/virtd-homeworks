## Задача 2

Выберите один из вариантов платформы в зависимости от задачи. Здесь нет однозначно верного ответа так как все зависит от конкретных условий: финансирование, компетенции специалистов, удобство использования, надежность, требования ИБ и законодательства, фазы луны.

Тип платформы:

- физические сервера;
- паравиртуализация;
- виртуализация уровня ОС;

Задачи:

- высоконагруженная база данных MySql, критичная к отказу;
- различные web-приложения;
- Windows-системы для использования бухгалтерским отделом;
- системы, выполняющие высокопроизводительные расчёты на GPU.

Объясните критерии выбора платформы в каждом случае.

## Решение
1. Высоконагруженная база данных MySQL, критичная к отказу
Выбор: Физические сервера
Обоснование:
Производительность: базы данных чувствительны к задержкам ввода/вывода, а виртуализация вносит оверхед.
Надёжность: можно настроить кластер на уровне железа (например, репликацию и отказоустойчивость с помощью Percona XtraDB Cluster).
Контроль: администраторы получают полный контроль над аппаратными ресурсами.
ИБ: проще обеспечить соответствие требованиям безопасности и законодательства (в т.ч. хранение персональных данных на выделенном оборудовании).

2. Различные web-приложения
Выбор: Виртуализация уровня ОС
Обоснование:
Гибкость: удобно запускать множество изолированных приложений на одном хосте.
Экономия ресурсов: контейнеры используют общее ядро, меньше накладных расходов.
Удобство CI/CD: контейнеры легко разворачивать, обновлять и масштабировать.
Стандартизация окружения: одно и то же приложение одинаково работает в тесте, деве и проде.

3. Windows-системы для использования бухгалтерским отделом
Выбор: Паравиртуализация
Обоснование:
Совместимость: бухгалтерские приложения часто требуют именно Windows.
Гибкость: виртуальные машины позволяют быстро развернуть, обновить и резервировать нужные экземпляры.
Безопасность: можно изолировать бухгалтерскую систему от других сегментов.
Резервирование: удобно делать снапшоты и быстро восстанавливать систему в случае сбоя.

4. Системы, выполняющие высокопроизводительные расчёты на GPU
Выбор: Физические сервера
Обоснование:
Доступ к железу: виртуализация плохо работает с GPU-пасстуром или требует дорогостоящих решений (например, NVIDIA vGPU).
Производительность: минимальные накладные расходы и прямой доступ к GPU.
Надёжность: важно исключить слои абстракции, которые могут стать узким местом.

## Задача 3

Выберите подходящую систему управления виртуализацией для предложенного сценария. Опишите ваш выбор.

Сценарии:

1. 100 виртуальных машин на базе Linux и Windows, общие задачи, нет особых требований. Преимущественно Windows based-инфраструктура, требуется реализация программных балансировщиков нагрузки, репликации данных и автоматизированного механизма создания резервных копий.
2. Требуется наиболее производительное бесплатное open source-решение для виртуализации небольшой (20-30 серверов) инфраструктуры на базе Linux и Windows виртуальных машин.
3. Необходимо бесплатное, максимально совместимое и производительное решение для виртуализации Windows-инфраструктуры.
4. Необходимо рабочее окружение для тестирования программного продукта на нескольких дистрибутивах Linux.

## Решение:
### Сценарий 1
**Выбор:**  
*Microsoft Hyper-V + System Center Virtual Machine Manager (SCVMM)*

**Обоснование:**
- Интеграция с Windows Server и Active Directory.  
- SCVMM обеспечивает централизованное управление и автоматизацию.  
- Поддержка балансировки нагрузки (NLB) и резервного копирования (Veeam, Windows Backup).  
- Возможность построения отказоустойчивых кластеров (Failover Clustering).  

### Сценарий 2
**Выбор:**  
*Proxmox VE (на базе KVM + LXC)*

**Обоснование:**
- Полностью open source, лицензия GNU AGPL.  
- Высокая производительность (гипервизор KVM уровня ядра).  
- Удобный веб-интерфейс, поддержка кластеризации и миграции ВМ.  
- Поддержка Linux и Windows виртуальных машин.  
- Встроенные средства резервного копирования (vzdump).  

### Сценарий 3
**Выбор:**  
*Microsoft Hyper-V Server (Core, бесплатная редакция)*

**Обоснование:**
- Полная совместимость с Windows системами.  
- Минимальные накладные расходы, высокая производительность.  
- Бесплатная редакция Hyper-V Server без GUI.  
- Управление через Hyper-V Manager, PowerShell или SCVMM.  
- Поддержка Hyper-V Replica и Active Directory.  

### Сценарий 4
**Выбор:**  
*VirtualBox или KVM*

**Обоснование:**
- **VirtualBox:** простой GUI, снапшоты, быстрое создание тестовых ВМ, кроссплатформенность.  
- **KVM:** высокая производительность, управление через `virt-manager` или `libvirt`.  
- Оба решения бесплатны и подходят для тестовых сред.

## Задача 4

Опишите возможные проблемы и недостатки гетерогенной среды виртуализации (использования нескольких систем управления виртуализацией одновременно) и что необходимо сделать для минимизации этих рисков и проблем. Если бы у вас был выбор, создавали бы вы гетерогенную среду или нет?

## Решение

Использование нескольких систем виртуализации одновременно может привести к ряду технических и организационных проблем:

1. **Сложность администрирования**
   - Разные интерфейсы управления, инструменты и политики.
   - Требуются специалисты с компетенциями по нескольким платформам одновременно.

2. **Увеличение затрат на обслуживание**
   - Необходимо больше времени на поддержку, обновления и мониторинг.
   - Повышается стоимость обучения персонала и сопровождения.

3. **Сложности интеграции**
   - Разные API и механизмы взаимодействия.
   - Проблемы при настройке единого мониторинга, резервного копирования или оркестрации.

4. **Несовместимость между системами**
   - Виртуальные машины могут использовать разные форматы дисков.
   - Миграция ВМ между гипервизорами может быть невозможна без конвертации и простоев.

5. **Повышенные риски отказов и ошибок**
   - Труднее контролировать обновления, патчи и безопасность в неоднородной среде.
   - Сложнее реализовать единые политики резервного копирования и восстановления.

### Меры для минимизации рисков

Чтобы уменьшить влияние указанных проблем, рекомендуется:

- **Стандартизировать процессы**: единые политики резервирования, обновлений и безопасности.  
- **Использовать централизованный мониторинг** (например, Zabbix, Grafana, Prometheus).  
- **Применять универсальные решения для бэкапов**.  
- **Документировать инфраструктуру** и поддерживать актуальную схему взаимодействия систем.  
- **Обучить персонал** и/или закрепить ответственность за каждую платформу.  
- **По возможности унифицировать** инфраструктуру, постепенно отказываясь от гетерогенности и переходя на одну основную систему.

### Личное мнение

Если есть возможность выбора — **гетерогенную среду я бы не создавал**, так как:
- она усложняет администрирование и повышает риски ошибок;
- увеличивает издержки на поддержку и обучение;
- уменьшает управляемость инфраструктуры, вносит элемент непредсказуемости в работе.

Оптимально использовать **одну систему виртуализации**, соответствующую основным требованиям компании (например, Proxmox для Linux-среды или Hyper-V для Windows). Гетерогенная среда оправдана только при наличии специфических требований, исключающих унификацию, или наследованных систем, которые невозможно объединить.
